# Blog 后台管理系统

配合 [blog-server](https://github.com/XiaoxinLab/blog-server) 使用的后台管理前端，纯前端单页应用，直接对接线上 API。

## 技术栈

- Vue 3（组合式 API）
- Vite 6（打包工具）
- Vue Router 4（路由，用 hash 模式，不需要服务器配重写规则）
- Axios（调接口）
- markdown-it（文章正文预览）

## 快速开始

```bash
npm install     # 装依赖
npm run dev     # 起开发服务器，默认 http://localhost:5174
npm run build   # 打包到 dist 目录
npm run preview # 本地预览打包结果
```

## 界面设计

方向是「墨与校对台」：给一个人深夜写博客的工作台，安静、精确、克制。

- **中性色**：深色用「墨」色阶（深蓝黑），浅色用同一套色阶的亮版。
  表面、边框、文字都从这一套里出，不给界面加多余的颜色。
- **强调色**：只有一个钢蓝。用在主按钮、选中态、图表的重点上，别的地方一律不用。
  深色底下配深色文字（对比度 5.5:1），浅色底下换成更深的蓝配白字。
- **字体**：界面中文用系统字体，数字、日期、键名用 JetBrains Mono（已随包安装，不走 CDN）。
- **图标**：统一用 lucide，16px、1.5 描边，颜色跟随文字层级。
- **签名细节**：左边那条 2px 的校对竖线，只出现在当前选中的导航项和表格鼠标划过的那一行。
- **间距**：所有数值都在 4px 刻度上。控件圆角 8、卡片 12、标签 4。
- **动效**：一条曲线 `cubic-bezier(0.22, 1, 0.36, 1)`，只动颜色和透明度，不做位移和缩放。

两处「有颜色」的地方是刻意留的：

1. 仪表盘和访问统计里的**趋势图**：细网格 + 面积折线，今天那一根用虚线标出来并标上数字。
2. **登录页**背景上极淡的稿纸格线。

改配色或者改风格，全部在 `src/styles/main.css` 顶部的 CSS 变量里，换主题不用翻别的文件。

## 界面风格

后台是**作者自己用的写作工具**，跟给读者看的博客前台是两回事，所以视觉上刻意跟博客区分开：

| | 前台博客 | 后台管理 |
|---|---|---|
| 底色 | 真黑 `#0a0a0f` | 哑光深灰 `#14161a` |
| 强调色 | 霓虹青 | 橙 `#ff7845` |
| 特效 | 粒子网、发光 | 没有，哑光工具感 |
| 圆角 | 大（6/12/20） | 小（4/8） |
| 字体 | Inter + Space Grotesk | Archivo + JetBrains Mono |

### 页面结构

顶部导航 + 内容区定宽居中（1240px），跟博客一个思路，但内容是自己的：

- **顶部导航**：就五个词，没有头像、没有退出按钮（一个人用的工具不需要登录装饰）
- **没有仪表盘**：打开就是文章列表，管理工具的第一屏应该是内容，不是图表
- **列表页左边一列筛选、右边一列内容**：左边是搜索 + 分类筛选，选中的项左边有一条橙色竖线
- **文章条目**：左边一条 2px 状态脊，橙色表示今天刚发出去的
- 界面里不写废话：不复述标题、不解释「25 是访问次数」、不标「单位：次」、不放没用的刷新按钮

配色和排版令牌都在 `src/styles/variants.css`，靠 `<html data-theme>` 切换深浅色。
字体在 `src/main.js` 里引入，不走 CDN。

对比度全部验过：正文、次级、弱化、占位文字四档都 ≥ 4.5:1
（占位文字也按 4.5:1 算，不用灰掉的默认值）。

预览图在 `design-previews/` 目录里。

## 接口地址

写在 `.env.development` 和 `.env.production` 里的 `VITE_API_BASE_URL`：

```
VITE_API_BASE_URL=https://qisui.asia/request
```

注意 `request` 这一段不能少。线上 Nginx 把 API 代理在 `/request` 路径下，
根路径 `/` 是前台博客的静态页面，直接请求根路径会拿到 HTML 而不是 JSON。

上传的图片存放在接口根目录下，所以图片完整地址是：

```
${VITE_API_BASE_URL}/${文件名}
```

例如 `https://qisui.asia/request/abc123.png`。

## 几个要注意的地方

1. **文章分类要填字典的「键」**。前台博客的分类筛选是拿字典的 `dict_key` 去匹配文章的
   `article_classification`，页面上显示的才是 `dict_value`。后台的下拉框存键、显示值，
   按这个来填，前台的分类筛选才点得动。

2. **下架的文章会从列表里消失**。后端用的是软删除，数据还在数据库里。
   所以后台额外提供了「按 ID 恢复」的输入框，输入 ID 就能恢复上架。

3. **字典的删除也是软删除**。`(dict_type, dict_key)` 上有唯一索引，
   删过的键虽然看不到了，但索引还被占着，再用同一个键新建会报「创建字典失败」。
   这也是「初始化默认分类」会提示哪几条失败的原因。

4. **后端的 `/dictionary/init` 接口目前是坏的**（返回「字典初始化失败」）。
   后台的「初始化默认分类」按钮会先试这个接口，失败就改用 `create` 接口逐条补齐。

5. **令牌有效期 1 天**。过期后接口会返回 `10101` 或 `10102`，
   前端拦截到之后会自动清掉登录态并跳回登录页。

## 部署

`npm run build` 之后把 `dist` 目录扔到 Nginx 的某个站点下就行。
因为用的是 hash 路由，不需要配 try_files 重写规则。

比如放到 `https://qisui.asia/admin/`：

```nginx
location /admin/ {
    alias /var/www/blog-admin/dist/;
    index index.html;
}
```
